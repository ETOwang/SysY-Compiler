# SysY Compiler Testing Framework

This directory contains a cross-platform testing framework for validating the correctness of the SysY compiler. The framework allows testing compilation and execution across different targets (ARM and RISC-V) and optimization levels.

## Directory Structure

- `cases/`: Test case files organized by category
  - `syntax/`: Tests for validating syntax parsing
  - `semantic/`: Tests for semantic analysis
  - `optimization/`: Tests for optimization correctness
  - `functional/`: Comprehensive functional tests
- `expected/`: Expected outputs for test cases
- `scripts/`: Testing utilities and scripts
- `emulators/`: Configuration files for architecture emulators
- `config.json`: Configuration file for testing framework (auto-generated)

## Setup

The testing framework now includes a cross-platform setup script that works on Windows, macOS, and Linux.

```bash
# On Linux or macOS
python3 scripts/setup.py

# On Windows
python scripts/setup.py
```

The setup script will:
1. Create the necessary directory structure
2. Check for required library files
3. Detect your operating system and recommend appropriate dependencies
4. Generate a default configuration file (`config.json`)

### Platform-Specific Setup

#### Linux

On Linux, you'll need to install:
- Python 3
- QEMU user-mode emulation
- ARM and RISC-V cross-compilers

```bash
sudo apt-get update
sudo apt-get install -y qemu-user gcc-arm-linux-gnueabihf gcc-riscv64-unknown-elf python3 python3-pip
```

For other distributions (Fedora, RHEL, etc.), use the appropriate package manager.

#### macOS

On macOS, you'll need:
- Python 3
- QEMU
- ARM and RISC-V toolchains

```bash
brew update
brew install qemu
brew install --cask gcc-arm-embedded
brew tap riscv/riscv
brew install riscv-gnu-toolchain
```

#### Windows

Windows users have three options:

1. **WSL2 (Recommended)** - Install the Windows Subsystem for Linux 2 and follow the Linux instructions.
   ```powershell
   wsl --install
   ```

2. **Direct Windows Setup** - Install the dependencies manually:
   - Python 3 from https://www.python.org/downloads/
   - MinGW for local testing from https://www.mingw-w64.org/downloads/
   - QEMU from https://www.qemu.org/download/#windows
   - ARM toolchain from https://developer.arm.com/tools-and-software/open-source-software/developer-tools/gnu-toolchain/downloads
   - RISC-V toolchain from https://github.com/riscv/riscv-gnu-toolchain

3. **Docker** - Use Docker containers with ARM and RISC-V images.

After installing the dependencies, update your `config.json` file with the correct paths.

## Configuration

The testing framework uses a `config.json` file for configuration. This file is automatically generated during setup, but you can manually edit it to match your environment:

```json
{
    "compiler_jar": "path/to/compiler-1.0-SNAPSHOT-jar-with-dependencies.jar",
    "targets": ["arm", "riscv"],
    "optimizations": ["O0", "O1", "O2"],
    "timeout": 30,
    "paths": {
        "arm_cc": "arm-linux-gnueabihf-gcc",
        "riscv_cc": "riscv64-unknown-elf-gcc",
        "qemu_arm": "qemu-arm",
        "qemu_riscv": "qemu-riscv64"
    }
}
```

To reset the configuration to defaults:

```bash
python3 scripts/run_tests.py --update-config
```

## SysY Library Functions

The SysY language includes library functions defined in `lib/sylib.h` that are automatically recognized by the compiler. The testing framework automatically links the compiled assembly with `lib/libsysy.a` to enable:

- Input functions: `getint()`, `getch()`, `getarray()`, etc.
- Output functions: `putint()`, `putch()`, `putarray()`, etc.
- Timing functions: `starttime()` and `stoptime()`

## Running Tests

The testing framework supports various testing scenarios:

### Basic Usage

Run all tests with default settings:
```bash
python3 scripts/run_tests.py
```

### Specific Category

Run tests in a specific category:
```bash
python3 scripts/run_tests.py --category syntax
```

### Specific File

Run a single test file:
```bash
python3 scripts/run_tests.py --file cases/functional/array.sy
```

### Specific Target or Optimization

Run tests with specific compiler options:
```bash
python3 scripts/run_tests.py --target arm --optimization O2
```

### Verbose Output

Enable detailed output for debugging:
```bash
python3 scripts/run_tests.py --verbose
```

## Adding New Tests

1. Create a SysY source file (`.sy`) in the appropriate category directory
2. Create a corresponding expected output file (`.out`) in the `expected/` directory
3. Optionally, add test configuration in a comment at the top of your test file:
   ```c
   // TEST_CONFIG: target=arm,riscv; optimization=O0,O1,O2; timeout=30
   ```

### Test Configuration Options

- `target`: Comma-separated list of targets to test (arm, riscv)
- `optimization`: Comma-separated list of optimization levels (O0, O1, O2)
- `timeout`: Maximum execution time in seconds

## Writing Expected Output Files

Expected output files (`.out`) in the `expected/` directory define what output a test should produce when executed correctly. These files are essential for automated verification of your compiler's correctness.

### Expected Output File Format

- **File Format**: Plain text files with `.out` extension
- **File Location**: Must be placed in the `expected/` directory
- **File Naming**: Must match the base name of the corresponding test file
  - Test file: `cases/functional/array.sy` → Expected output: `expected/array.out`
- **Content**: Only include the exact output that the program would produce when run
- **Encoding**: UTF-8 text encoding is recommended

### Output Content Guidelines

1. **Exact Match**: Include exactly what your test program outputs using functions like `putint()`, `putch()`, etc.
2. **Line Breaks**: Pay attention to line breaks (`\n`) - they must match exactly
3. **Whitespace**: All spaces, tabs, and line breaks are significant and must match
4. **No Extra Information**: Do not include compiler messages, timing information, or exit codes
5. **Empty File**: For tests of syntax/semantic errors, the output file can be empty

### How the Framework Uses Output Files

The testing framework:
1. Compiles the test program to assembly
2. Links it with the SysY library
3. Executes the resulting program
4. Captures all stdout output
5. Checks if the expected output (from `.out` file) is contained within the actual output
6. Reports test success or failure based on this comparison

### Examples

**Example 1: Simple output**

`expected/simple.out`:
```
42
```

**Example 2: Multiple lines with precise formatting**

`expected/formatted.out`:
```
Line 1
  Indented line 2
Line 3
```

**Example 3: Character output (including special characters)**

`expected/chars.out`:
```
Hello, World!
Special chars: +-*/
```

### Common Mistakes to Avoid

1. **Including Exit Codes**: Don't include `Exit code: 0` - the framework adds this
2. **Compiler Messages**: Don't include any compiler output
3. **Invisible Characters**: Be careful with trailing spaces or invisible characters
4. **Windows Line Endings**: Ensure your files use the correct line endings (LF, not CRLF)
5. **Missing Line Breaks**: If your program outputs a line break at the end, include it

### Testing Input-Dependent Programs

For programs that use input functions (`getint()`, `getarray()`, etc.):

1. The test framework does not currently support automated input feeding
2. Consider modifying your test to use hardcoded values instead of input functions
3. Alternatively, include input instructions in comments for manual testing

## Troubleshooting

### Cross-Compiler Not Found

If the testing framework cannot find the cross-compilers, make sure they are installed and in your PATH, or update the paths in `config.json`.

### QEMU Issues

If you encounter issues with QEMU:
- Ensure QEMU is installed correctly
- Check if you need to install additional libraries for the target architectures
- Verify that the test cases don't rely on specific hardware features

### Library File Issues

If you see errors about missing `libsysy.a` or `sylib.h`:
1. Check that these files exist in the `lib/` directory
2. Rebuild the library if needed:
   ```bash
   cd lib
   make clean
   make
   ```
